# 分支浏览与切换、单次提交挑选、UE 资产贮藏开发计划

状态：已实现首版主体工作流，仍有手工界面验收及后续体验项目。日期：2026-11-09。实际实现、使用方式和验证边界见 [实现说明](fork-workflows-implementation.md)；下文保留设计目标，不代表每项体验细节均已交付。

依据：本地 `main`，调研时 HEAD 为 `c11ffaf`，工作区无已有修改。只阅读源码和命令帮助，未运行测试、未操作用户 SVN 工作副本。当前程序版本字段为 `0.6.5-rc.3`。

## 1. 交付目标与范围

完成三个连贯的工作流：

1. 在常驻中文界面中浏览分支，看到当前分支，并切换整个工作副本。
2. 当前工作副本留在 publish，浏览 dev 的历史，选择一次提交，预览、应用并处理冲突，最后由用户审阅和提交。
3. 在 dev 保存包括 `.uasset`、`.umap` 在内的未完成工作，确认保存成功后移除选定修改；返回 dev 后应用或弹出贮藏。

保留现有中文和其他语言支持，复用更新、提交、日志、文本差异和工作区导航。不自动向服务器提交，不新增 Git 仓库转换，也不接入 UE 编辑器来解析资产内容。

首次交付支持：全工作副本切换；单个 revision 的挑选；文本/二进制内容冲突的基本处理；属性和树冲突的展示、手工处理后的确认；整文件贮藏以及原有文本分块贮藏。

暂不实现：多个 revision 的批量挑选、完整分支拓扑图、分支创建/删除、跨仓库合并、自动解决任意树冲突、内置蓝图节点合并、贮藏复制/移动历史、自动后台贮藏。不能处理的状态明确列出并阻止相应操作，不静默跳过后声称全部成功。

### 1.1 交互参考：Fork Git 客户端

用户日常使用 Fork，本项目的界面与操作入口以 Fork 为主要参考，SmartSVN 仅用于核对 SVN 工作流。参考的是公开界面中的信息层次与常用操作路径，产品继续使用 OrcaSVN 的品牌、中文文案和已有视觉资源。

研究依据为 Fork 官网公开的 Windows 历史、工作区变更及并排 Diff 截图，以及其功能介绍。截图展示的是公开示例，不表示已核对用户本机安装版本的全部细节。

第一版采用稳定的桌面工作台：左侧常驻导航，中央历史/工作区，详情区展示提交、文件与差异；减少“看一个提交、看一个文件就离开原页面”的跳转。已有 Vue 页面和 DiffViewer 改造成可嵌入的视图，按功能逐步接入，不一次性重写所有路由。

建议工作台内容：

```text
顶部：工作副本名称与路径 | 当前分支 | 刷新 | 更新 | 提交 | 贮藏 | 活动
左侧：本地更改（数量）
      历史
      收藏分支
      分支：dev / publish / ...
      标签（仅已配置时显示）
      贮藏（数量）
      冲突（存在时显示）
中央：所选分支的提交列表，或本地更改列表
详情：提交说明、受影响文件、文本 Diff / 资产信息
底部：当前操作进度、结果和可展开日志
```

布局使用可拖动分隔线，保存用户调整的宽度。界面紧凑，常用内容占据主要面积；不增加大面积装饰卡片或重复页头。现有刷新、更新、提交操作继续使用真实 SVN 名称。

### 1.2 Fork 操作方式与 SVN 语义的对应

分支：左侧列表是主要入口，顶部按钮是快捷入口。当前工作副本分支始终有单独标记。单击其他分支仅浏览该分支历史，不修改工作副本；右键“切换工作副本到此分支…”或双击后进入切换确认。历史区明确显示“浏览 dev；当前工作副本 publish”。

历史：选中一条记录，详情区立即显示提交说明、文件列表和差异；保留列表选中项、分页和滚动位置。右键提供“挑选此提交到当前分支…”、“复制版本号”、“查看详情”等。挑选目标必须是当前真实工作副本，不由正在浏览的历史分支推断。

贮藏：左侧常驻贮藏列表，显示名称、来源分支、时间、文件数和容量。单击查看内容；右键/详情工具条提供 Apply、Pop、完整导出、删除。工作区文件菜单提供“贮藏所选文件…”，文本块菜单继续提供适用的分块贮藏。创建贮藏后直接更新计数和列表。

工作区提交：采用文件列表与 Diff 并列、提交说明靠近提交动作的布局。文件使用“待提交/本次已选择”等文案。勾选只是本次提交选择，不声称已保存 Git index 快照；若文件之后被修改，需要更新差异并在提交前重新核对。第一版不新增逐行提交，仅保留已有按文件提交与文本分块贮藏。

冲突：左侧和当前任务显示待处理数量，选中冲突就能看双方信息和当前结果；从冲突处理返回后仍保留原合并任务。内容处理、标记解决与最终提交是独立动作。

活动：重要任务展示进度、来源、目标、阶段及完整输出。切页不关闭任务；没有任务时不常驻空面板。后端操作状态是权威来源，不能只有短暂 toast。

键盘：为分支过滤、日志搜索、前后文件和主操作提供可发现的快捷键；显示在菜单中。快捷键不绕过预检查和覆盖确认，第一版不实现以拖拽直接执行合并。

以下 Fork/Git 元素不直接移植：Stage/Unstage、Fetch/Pull/Push、Rebase、Amend、Reflog 和本地/远端分支双份模型。SVN 界面显示更新、提交和仓库分支；Stash 仍标注为本机数据。

历史第一版使用 revision、作者、时间、分支标签及相对于目标的合并状态。没有复制来源和 mergeinfo 证据时不绘制父子/合并连线，也不把全仓库 revision 的相邻顺序当作提交父子关系。真正的分支关系图仍为后续功能。

多工作副本标签页是后续体验增强：第一版先保留最近工作副本切换并将当前身份显示清楚；增加标签页前必须把当前全局工作区状态隔离成每工作副本独立状态，不仅增加一排外观标签。

### 1.3 对原实现顺序的调整

共同基础阶段同时定义工作台选中状态：工作副本身份、正在浏览的来源分支、选中 revision、选中文件和当前操作 ID。实现分支阶段接入左侧列表与顶部快捷入口；实现挑选阶段将日志详情和 Diff 嵌入；实现 Stash 阶段加入侧栏记录和文件菜单。布局按功能增量演进，不另开一次覆盖全项目的 UI 重写。

验收增加：单击分支不会切换工作副本；从 dev 历史挑选到 publish 时方向始终可见；查看 Diff 后返回选中项和滚动位置不丢；Apply 与 Pop 区别清晰；文件勾选不误导为冻结内容；中断或失败操作可从活动区继续查看。

## 2. 当前源码事实

- `src/api/svn.ts` 已有 `svnSwitch`、`svnMerge`、`svnResolve`，`src-tauri/src/main.rs` 已注册对应 Tauri 命令。
- `svn/operations.rs::switch_cmd` 目前直接调用 `svn switch URL`；`merge` 只封装 `svn merge -r start:end SOURCE`，尚无挑选提交、预览和合并会话。
- `LogView.vue` 绑定当前本地路径读取历史，不能独立选择来源分支。打开历史文件差异时，其来源信息也需要随远端日志目标一起更新。
- `StashView.vue` 已有创建、Apply、Pop、删除、导出文本 patch，以及部分未跟踪文件捕获。创建时先保存记录，再反向应用文本补丁、删除选定未跟踪文件。
- `stores/stash.ts` 将补丁和 Base64 内容存入 WebView `localStorage`；`main.rs` 将未跟踪内容单次捕获总量限制为 2 MiB。
- 受控文件贮藏依赖统一文本 diff 的 `@@` 块，未覆盖受控二进制、属性与完整 SVN 调度状态。现有记录仅绑定工作区路径，缺少仓库 UUID、来源 URL 和逐文件基础版本。
- `SvnInfo` 没有仓库 UUID、工作副本根路径、相对仓库 URL 等身份字段；`SvnStatus` 虽能把树冲突归为 conflicted，却没有保留冲突种类和双方来源。
- `useWorkspace.ts` 会使用 `svnInfoCache.ts` 中按路径缓存的 URL 元数据，TTL 为 24 小时；`refreshStatusAfterMutation` 只明确失效工作区快照。因此不能把现有“强制状态刷新”视为分支身份的强制重读。
- 日志、更新页、Diff 导航和后端状态扫描各有缓存。现有部分请求通过“本地路径仍相同”判断有效，同一路径切换分支后不再充分。
- `executor.rs` 使用参数数组调用 SVN，当前默认 120 秒超时，成功时主要返回 stdout。缺少跨功能的工作副本写操作互斥、长操作进度和中断恢复记录。
- UI 状态可经过 `.gitignore` 过滤；写操作前的检查必须使用后端新读取的完整 SVN 状态，不能依赖过滤后的页面列表。

## 3. 共同基础，先于三个功能落地

### 3.1 工作副本身份

扩展本地和远端 info 解析，区分：

- 本地工作副本：规范化绝对根路径、仓库 UUID、仓库根 URL、当前 URL、相对仓库路径、根节点基础版本、depth。
- 远端浏览目标：仓库 UUID、仓库根 URL、目标 URL、节点种类、查询版本、peg revision。
- 逐路径状态：本地相对路径、节点种类、基础 revision、文本/属性状态、复制/移动信息、switched、冲突种类、外部工作副本边界。

根目录 revision 不是所有文件的 revision。允许普通状态展示混合版本；挑选合并前检查并要求先更新到一致、受支持的工作副本状态，不自动添加 `--allow-mixed-revisions`。

本地路径按 Windows 路径规则规范化；仓库 URL 保留路径大小写，按 URL 组件编码。对含空格、中文、`@` 的路径统一处理 SVN peg 语法，`--` 参数边界与 peg 消歧分别实现。

### 3.2 写操作协调

增加按真实工作副本根路径管理的后端写操作门闩。更新、提交、切换、合并、解决冲突、贮藏移除/恢复、还原、Add/Delete/Clean Up 接入同一入口；前端按钮禁用只是反馈，后端再次检查。

写操作参数包含捕获时的工作副本身份。后端开始写入前重新读身份和完整状态，身份已变则拒绝旧请求。已经在运行的写操作不因前端切换页面而转移目标。

操作结果区分：完成、存在冲突、部分完成、失败、已中断且需检查。命令退出码与“是否存在业务冲突”分别展示。错误时也扫描实际状态，保留原始输出和可复制的日志。

只新增本功能所需的结构化结果，不重写全部旧命令。旧 `CommandResult` 可以兼容扩展；新流程使用明确的操作 ID、阶段、受影响路径、冲突和结束状态。

### 3.3 进度、超时和恢复

- 读取查询可以继续采用有限超时；大型切换、合并和文件快照使用适合长操作的配置、进度事件和操作日志，避免所有步骤固定共用 120 秒。
- 如需结构化命令输出，后端保留 exit status、stdout、stderr；不从界面文本推断唯一状态。
- 中断 SVN 写操作可能留下部分变化，界面必须明确告知，不承诺取消等于回滚。保留会话，重新扫描后提供检查、继续或清理指引。
- 不复制或恢复 `.svn/wc.db`。工作副本恢复通过 SVN 命令和受控文件快照完成。
- 外部客户端、IDE、UE 不受应用门闩控制；正式写入前重验计划，进行大文件快照时核对源文件是否在读取期间变化，发现变化停止并保留已有备份。

### 3.4 缓存与请求版本

增加工作副本内容/身份代次。缓存至少绑定规范化工作副本根、UUID、当前 URL 和代次；远端日志缓存另绑定来源 URL、peg、revision 范围、过滤条件和分页位置。

Switch 完成或部分失败后：失效 info 元数据、工作区快照、后端扫描基线、相关 Log/Update/Diff 缓存，强制重读本地 info 与状态。旧异步响应不能覆盖新分支画面；查询失败显示未验证，不能继续显示旧分支为已确认。

合并、Resolve、Stash 操作后也刷新相关状态和预览计划。UI 过滤不参与后端判断工作副本是否干净。

## 4. 分支浏览与切换

### 4.1 界面

保留现有“切换本地工作区路径”控件，以 Fork 风格的左侧常驻分支列表为主要入口，顶部新增独立的当前分支快捷按钮，避免混淆工作副本切换、历史浏览和分支切换。

分支选择器显示当前分支、完整 URL、收藏/最近使用、配置目录中的候选分支、刷新和按需展开的远端目录浏览。没有布局配置时直接显示完整 URL，并允许手动选取目录。

用户的配置示例：项目根 URL 为 `…/svn/ue5/ugame`，固定分支为 `dev`、`publish`；也支持其他项目的 `trunk`、`branches/*`、`tags/*`。规则是本地识别配置，不修改服务器布局。不把任意目录自动认定为同源可切换分支。

### 4.2 后端

- 用 `svn list --xml` 按层读取远端目录，避免递归扫描全仓库。
- 用远端 `info --xml` 确认目标存在、是目录、仓库 UUID 一致。
- 区分同仓库与具有共同祖先：UUID 一致并不证明 ancestry 相容，最终交由 SVN 默认祖先检查；不自动使用 `--ignore-ancestry` 或 `--force`。
- 默认只支持对完整工作副本根执行切换；保留已有检出深度，不擅自扩充稀疏工作副本。
- 显示外部工作副本信息。第一版不递归切换 externals；如目标 external 定义发生改变，提示其尚需单独更新，不能标成已同步。

### 4.3 操作流程

1. 选择目标，解析当前和目标身份，取得目标固定 revision，展示切换方向。
2. 新读完整状态。存在受控文件修改、属性变化、调度变更、冲突或局部 switched 子树时默认阻止切换，列出具体原因。
3. 可选择“去提交”“去贮藏”“取消”。未支持贮藏的变化不能被掩盖；贮藏结束后重新检查全部剩余状态，不能假定工作区已干净。
4. 未跟踪文件本身不一概阻止切换。列出与预计新增路径冲突的项目；正式执行保留 SVN 的障碍检查，不强制覆盖。
5. 用户确认后，后端重新校验计划和目标身份，执行固定目标版本的 Switch，并保留进度。
6. 无论成功失败都重读实际 URL、深度、子树状态和冲突。成功后才显示新分支；部分切换则明确展示不一致路径。

`svn switch` 在本机 SVN 1.14.5 中没有 `--dry-run`。切换窗口展示的是预检查和变更概览，不能标注为 SVN 已验证的完整演练。网络失败或祖先不相容不自动尝试强制切换。

### 4.4 验收

- 固定兄弟目录布局和标准 branches 布局均能浏览，中文/空格/@ 路径正确。
- dev→publish→dev 后 info、日志、更新页和差异来源均正确，旧异步响应不回填。
- 本地修改被 UI 忽略规则隐藏时仍被检查发现。
- 不同 UUID、不存在目录、权限错误、祖先不相容各自给出可辨认错误。
- 不覆盖未跟踪障碍，不改变外部工作副本，不触碰相邻 `.git` 元数据。
- 处理中断后真实混合状态可见，不能只因根 URL 改变就报告完整成功。

## 5. 单次提交挑选及冲突处理

### 5.1 日志来源与目标分开

Log 视图接入左侧分支选择，并保留来源分支选择器，默认浏览当前分支，但允许本地仍为 publish 时查看 dev。明确显示“正在浏览 dev；将应用到 publish”。选择来源只查询历史，不执行 Switch。提交详情与文件 Diff 优先在同一工作台显示，右键菜单提供挑选入口。

日志详情增加“挑选到当前分支…”按钮。第一版一次选择一个 revision，整个来源分支子树内的该次改动一起处理；不支持挑选提交中的任意几个文件，避免不完整变更和错误 mergeinfo。

远端日志的文件 Diff、删除文件的历史 peg、分页游标、作者筛选均绑定来源 URL。一个 SVN revision 可能同时改多个分支，预览要区分来源子树内和范围外的路径，不能把整仓库 changed_paths 当成全要合并的文件。

### 5.2 查询与计划

- 新增 `svn mergeinfo --show-revs eligible/merged` 查询，绑定当前真实工作副本。
- 保留 unknown、eligible、merged、可能部分合并等状态；继承/子树 mergeinfo 不能仅凭根属性简化为已全部合并。
- SVN 不支持或无法确认时展示未知与原因，不能因查询失败认定未合并。遇到无法可靠判断的复杂子树状态，第一版阻止一键挑选并说明原因。
- 同分支、不同仓库、存在冲突、受控本地修改、局部 switched、未完成写会话、未支持的 sparse/mixed-revision 情况先处理，再生成计划。

计划保存目标身份与状态指纹、来源 URL、来源 peg、单个 revision、预览文件、查询结果及时间。来源分支/版本或目标状态改变后预览失效。

### 5.3 执行语义

新增按 revision 的接口，使用 `svn merge -c R SOURCE@PEG TARGET`，不复用 UI 让用户填写 `R-1:R`。命令显式指定目标路径和 `--accept postpone`，采用正常 merge tracking。

“预览”使用相同参数的 `--dry-run`。来源已被固定定位，但目标之后仍可能变化，因此正式应用前重新验证目标状态。

默认不使用 `--record-only`、`--ignore-ancestry`、`--force`、`--allow-mixed-revisions`。预览不能证明功能依赖齐全，也不能证明实际执行必然无冲突。

### 5.4 合并会话

从干净、已检查的目标开始，保存计划、受影响路径、原状态和必要恢复材料。应用后进入以下一种状态：

- 已应用，等待审阅和提交。
- 已应用但有冲突，进入冲突列表。
- 无实际变化或已合并，展示原因，不伪造新提交。
- 失败/部分应用，展示实际残留和日志。

通过执行输出以及新读取的 `status --xml`、必要的 `info --xml` 判断结果；不只依赖退出码或英文 stdout 文本。

成功后跳转到现有工作区/提交页，预填来源分支与 revision 的提交说明。将所有相关目录的 mergeinfo 属性变化纳入待审阅清单。只有提交成功后，才显示已提交到目标分支。

“取消预览”不修改文件。“撤销本次应用”必须核对会话拥有的变化：先备份当前结果，确认没有混入新的外部编辑，再按会话路径恢复。新增文件的清理也要核对来源与内容；不能对整个项目直接递归 Revert，也不能恢复过期的 `.svn` 数据。无法安全区分时保留现状并给出人工处理路径。

### 5.5 冲突处理界面

新增冲突页面，Update、Switch、Cherry-pick 共用 SVN 冲突呈现。每个冲突至少显示路径、种类、操作来源、相关版本以及当前是否已处理。

文本内容冲突：显示基线、本地、传入内容及最终工作文件；第一版复用当前差异显示，允许调用配置的外部编辑/三方合并工具。保存后选择“保留当前处理结果并标记解决”。检测明显残留冲突标记给出提示，但不以此代替用户判断。

二进制内容冲突：显示大小、摘要、版本与双方实际来源；选择保留当前、使用传入版本或导出双方。覆盖前先保存当前文件；以 SVN 生成/报告的冲突版本为依据，不能简单把任意来源 `HEAD` 当成 incoming，也不能在不同操作中固定假定左右侧含义相同。

属性冲突：展示属性名、基线和双方值，允许按属性确认最终结果，标记后重新查询。树冲突：展示 incoming/local 的删除、增加、移动等动作与路径，第一版只自动执行明确支持且验证过的策略；其他情况提供人工整理文件、打开目录和复制诊断的入口，整理后重新检查并由用户确认 resolved。不会默认一键批量忽略树冲突。

Resolve 策略在后端使用枚举白名单。手工结果使用 `--accept working`；其他策略只对已验证适用的冲突种类开放。保留备份后才执行覆盖类策略；执行后仍有冲突则保持未解决。

资产修改可能要求 UE 编辑器关闭以释放文件；发生占用时指出具体路径，不自动结束用户进程。

### 5.6 验收

- publish 浏览 dev 并挑选一次提交，目标分支始终没有切换。
- 普通文本新增/修改/删除、二进制修改都能按 SVN 语义应用。
- 重复挑选正确识别 merged/无变化；未知与部分合并状态不误报。
- 预览不修改工作区；正式应用后更改文件与 mergeinfo 进入审阅列表。
- 目标发生新编辑后旧计划被拒绝；一次提交包含其他分支修改时范围显示和应用正确。
- 文本、二进制、属性、树冲突分别展示；手工确认后状态消失，退出 0 但有冲突时仍有警告。
- SVN 失败、应用中断、UI 关闭后重新打开能检查残留；没有自动提交。
- 撤销仅在可以证明归属时处理会话变化，无法证明时保留全部内容。

## 6. 面向 UE 资产的 Stash 增强

### 6.1 界面与支持边界

继续使用贮藏列表和 Create/Apply/Pop/Delete 操作，将列表接入左侧常驻导航并在详情区显示内容，提供类似 Fork 的上下文菜单。创建窗口同时展示代码、资产和其他选定文件，支持按目录勾选并显示完整路径、状态、文件数量及总大小。

两种保存模式：

- 整文件：保存字节、必要属性和 SVN 调度信息。二进制默认使用，文本也可使用。
- 文本分块：保留原有功能。必须是支持的文本、没有复杂调度/属性变化，不能把二进制伪装成文本。该模式的记录同样转由后端落盘。

第一版整文件覆盖：普通受控修改、普通无历史新增/安排删除、必要的普通目录新增/删除、未跟踪文件/目录。父子依赖必须完整选择；不能选中删除目录却漏掉内部待保存修改。

复制/移动历史、替换节点、冲突状态、external、局部 switched、符号链接/目录联接等不可证明可恢复的情况明确列为不支持。带属性变化的文件不能只存正文：要么整文件模式同时保存属性，要么阻止保存。未完成合并会话、mergeinfo 变化不纳入普通 WIP 贮藏。

UE 中移动资产可能产生重定向器及新增/删除文件。按 SVN 实际状态处理：普通新增/删除可支持；带 history 的移动第一版整体阻止并说明，不丢失复制来源信息后声称支持。

忽略项默认不自动加入贮藏；选择未跟踪目录时先展开预览实际收集范围，排除 `.svn`、`.git` 和嵌套工作副本。目录中的不支持项要显式列出。不能静默只保存部分内容，再递归删除整个目录。

### 6.2 磁盘格式

使用 Tauri 提供的应用本地数据目录，建议结构：

```text
stashes/v2/<stash-id>/
  manifest.json
  payload/<内部对象ID>
  patches/<内部对象ID>.patch
  journal.json
```

manifest 至少记录：格式版本、ID、名称、时间、原工作副本路径、UUID、仓库根、来源 URL、根节点版本、逐路径基础版本和状态、节点类型、保存模式、BASE/WIP 内容引用、内容长度与 SHA-256、基础与工作属性、创建/恢复阶段。

payload 使用内部 ID，工作区相对路径只存于 manifest，防止用户路径影响存储目录。大文件由 Rust 分块读写、计算摘要，不经 Base64 或完整文件内容 IPC 往返。读取、校验、持久化步骤失败时不能清理原文件。

存储目录允许之后在设置中选择；变更位置需有独立迁移流程，不能因设置变化让旧记录消失。容量限制改为显示实际大小、可用空间及明确的存储策略，首版不自动淘汰旧贮藏。

不以扩展名识别所有二进制；按内容和 SVN MIME 属性判断。`.uasset/.umap` 明确走字节快照，保持原始编码、换行和数据。

### 6.3 创建：保存与移除分开记录

1. 后端接收用户选择，获取门闩，重新读取真实身份和完整状态，展开目录依赖并形成执行计划。
2. 检查磁盘空间、可读取性和文件状态。保存选定正文、基础版本需要的信息、工作属性及调度信息。缺失/已删除项区分“本来不存在的 WIP”与“BASE 中存在”。
3. 写临时贮藏目录，计算摘要，完成后重读校验；manifest 标记内容已完整保存，再发布为可用记录。文件读写期间发生变化时中止清理阶段。
4. 开始清理前再次检查选定文件指纹，按明确的逐项计划恢复选定修改。无历史 Added 的 Revert 会留下本地文件，普通删除会恢复 BASE，必须分别处理并验证最终调度；不能只调用一次递归 Revert 就视为完成。
5. 对未跟踪项仅移除确已保存且内容未变的对象；目录非空或发现新增内容时停止，不递归删除未捕获内容。
6. 逐项更新 journal，并新读状态确认选中内容已移除、未选中内容仍在。应用可以展示“已保存，移除未完成”，保留所有恢复材料。

SVN 与文件系统组合操作不是单个原子事务。计划保证先有可校验快照再清理，并记录中断位置，不承诺进程任意时刻退出都能自动恢复到操作前。

### 6.4 Apply / Pop

1. 预检贮藏结构、摘要、所有目标路径和当前身份。不同 UUID 拒绝；不同 URL 默认阻止一键恢复，提示回到来源分支。
2. 工作副本目录移动但 UUID/URL 一致时，可以明确重新绑定；需要核对工作副本身份和逐文件基线，不能只修改字符串路径。
3. 当前目标涉及的文件有本地变化、占用或结构障碍时逐项展示，不直接覆盖。保存一份恢复前快照，形成恢复会话。
4. 基线未变化且目标无修改时，恢复正文/属性并重建 Added/Deleted 等调度；未跟踪文件恢复后仍保持未跟踪。
5. 如果 BASE 或当前文件已变化，文本模式进行预演或三方对比；二进制只展示基线、当前和贮藏版本，不自动合并字节。
6. 已等于贮藏结果的文件识别为已恢复，防止中断后重复应用。不同内容产生应用内部的贮藏冲突，可选择保留当前、使用贮藏版本（先备份）、导出两份或取消。该冲突不能假装成 SVN 工作副本冲突，也不能靠 `svn resolve` 消除。
7. 恢复完成后逐项校验正文、属性和状态。Apply 保留记录；Pop 只有全部选定内容成功恢复、无未解决/跳过项并完成校验后才移除活动记录。部分成功保留记录和进度。

恢复前快照与失败记录不能被 Pop 顺手删除。删除贮藏仅删除应用持有的数据，不执行任何工作副本还原。操作日志明确区分“数据记录删除”与“工作文件删除”。

文本 BASE 的仓库表示可能与工作文件的 EOL、keywords 展开不同。不能直接把 `svn cat` 返回字节与本地文本字节比较；整文件保存实际 WIP 字节，基线比较结合 revision、属性和文本转换规则，文本合并交给支持 SVN 语义的路径。

### 6.5 恢复日志与路径边界

创建/恢复阶段至少记录 planned、saved、removing/restoring、complete、partial。启动扫描发现未完成会话时展示具体阶段和已完成路径，先检查现状再提供恢复入口，不无条件重放删除或补丁。

拒绝相对路径字段中的绝对路径、`..`、Windows 盘符跳转、符号链接和 reparse point 越界。校验实际解析后的读写目标位于指定工作副本和应用数据根内；排除 metadata 与 external。文件被占用、磁盘满、ACL 拒绝、摘要不符时保留源和已存快照，不通过其他工具绕过系统访问策略。

### 6.6 旧记录迁移

- 读取旧 `orcasvn-stashes` 数据，逐条写入 v2 目录并校验。
- 缺失 UUID/URL/BASE 信息标为 legacy，不能凭当前分支替旧记录猜测原始身份。
- 旧 patch 与未跟踪文件原样保存，继续提供适用的恢复/导出入口；恢复前要求用户确认来源并进行预检查。
- 单条成功才记迁移状态；失败保留原 localStorage，不批量清空。迁移重试幂等，不重复制造记录。
- 新导出应是完整包，包含 manifest、正文和 patch；保留“仅导出文本补丁”并明确它不包含全部资产/未跟踪数据。导入同样逐项检查路径和摘要。

### 6.7 验收

- 受控 `.uasset`、`.umap` 修改以及大于 2 MiB 的未跟踪资产按字节和摘要往返一致。
- 普通新增、删除、目录依赖、空目录、属性和混合版本基线被准确记录或明确拒绝。
- 创建后仅所选内容移除；未选中内容、目录中新出现的文件和忽略项不被误删。
- Apply 保留记录；Pop 全成功才移除，出现任意部分失败时仍能恢复。
- 原路径切到另一分支时阻止误恢复；工作副本搬家时明确重绑定；UUID 不同必拒绝。
- UE 占用、文件读取中变化、磁盘满、进程中断和文件损坏均保留可恢复材料。
- 旧 patch 与未跟踪内容迁移后仍可恢复；缺失来源显示 legacy，不伪造字段。
- 文本分块贮藏继续可用，CRLF/UTF-8/无尾换行不退化。

## 8. 实现顺序

1. 共同基础：身份与 XML 字段、原始状态预检查、写操作协调、请求代次和缓存失效、操作结果，以及 Fork 风格工作台的选中/浏览状态。先保证现有更新提交不退化。
2. 分支浏览与 Switch：布局、远端按层浏览、顶部入口、预检、进度及部分失败展示。
3. 单次挑选与冲突：远端日志来源、eligible 查询、dry-run、应用会话、冲突基础界面、mergeinfo 审阅。
4. Stash v2：后端磁盘存储与校验先完成，再接整文件创建/恢复，最后迁移旧记录、完整包导入导出和原文本分块兼容。
5. 连贯验收：dev 贮藏→切 publish→挑选 dev 提交→处理冲突→用户提交→切回 dev→恢复资产贮藏。

这只是实现与审查顺序，不要求每完成一步都向用户重新申请开发授权。当前请求仅规划，尚不执行以上实现。

## 10. 关键决策

- 保持 SVN 的分支与 mergeinfo 语义，提供 Git 风格入口，但不伪造 Git 提交/本地分支模型。
- Switch 只做预检；Cherry-pick 才有 SVN 原生 dry-run。
- 先完善身份、互斥与缓存，再增加操作按钮。
- Stash 的磁盘持久化与恢复日志是核心，调大 localStorage 限制不能满足 UE 资产需求。
- 二进制不自动内容合并；文本/属性/树冲突分别处理。
- 所有破坏性步骤前先保存可验证材料，部分失败可检查可恢复，不承诺跨 SVN/文件系统原子事务。
- 基础版本变化时不直接覆盖资产；跨分支恢复默认阻止。
- 旧贮藏必须可迁移并保留原始数据；不支持的状态透明列出。
